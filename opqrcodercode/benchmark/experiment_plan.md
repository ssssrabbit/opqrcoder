# OPQR Code 読み取り評価 実験計画書

**バージョン**: 1.0  
**作成日**: 2026-04-16  
**対象論文**: "OPQR Code: Embedding Pixel Art Images into QR Code Padding Codewords"

---

## 1. 実験目的

OPQR Code（QR コードの padding codeword 領域に画像を埋め込む手法）について、以下の観点で読み取り性能を定量評価する。

1. **デジタル評価**（Phase 1 — 実施済み）: 生成 PNG をソフトウェアデコーダで直接デコードし、理想条件下での読み取り成功率を測定する。
2. **印刷・スキャン評価**（Phase 2 — TBD）: 標準的なプリンタ出力を平台スキャナで読み取り、紙媒体での劣化耐性を測定する。
3. **カメラ評価**（Phase 3 — TBD）: スマートフォンカメラで撮影した画像をデコードし、現実的なユースケースでの読み取り性能を測定する。

## 4. Phase 1：デジタル評価（実施済み）

### 4.1 プロトコル

- 生成 PNG（セル 8px・マージン 4 cells）を PIL で読み込み、ZBar / ZXing で直接デコード。
- デコード結果が `OPQR code` と完全一致する場合を「成功」とする。
- スクリプト: `evaluate_qr.py`、結果: `eval_results.json` / `comparison_table.md`

### 4.2 結果サマリ（v07, n=10 画像）

| 手法 | ZBar | ZXing |
|------|------|-------|
| 標準 QR (ECL=L) | **100%** | **100%** |
| 中央ロゴ 15% (ECL=L) | 70% | 100% |
| 中央ロゴ 30% (ECL=H) | 50% | 100% |
| ECC 上書き ≤7% (ECL=L) | **0%** | **0%** |
| ECC 上書き ≤30% (ECL=H) | **0%** | **0%** |
| ECC 全上書き (ECL=H) | **0%** | **0%** |
| **OPQR noise=0%** | 80% | **100%** |
| **OPQR noise=5%〜30%** | **100%** | **100%** |
| **OPQR noise=5%〜20% (dither ON)** | **100%** | **100%** |

> **考察**: ECC 容量を超えない範囲での上書き（`ecc_overlay`）は ZBar・ZXing ともに 0% となった。これは上書きされたモジュールが ECC 容量内であっても、固定値ではなく画像由来の任意ビット列であるため誤り訂正が機能しないことを示す。OPQR は padding codeword のみを変更するため ECC を一切消費せず、理論上 100% の読み取り成功率を持つ。

## 5. Phase 2：印刷・スキャン評価（TBD）

### 5.1 目的

デジタルデータが紙媒体に変換される際の印刷ノイズ・スキャンノイズ耐性を測定する。

### 5.2 印刷条件

| 項目 | 仕様 |
|------|------|
| プリンタ | レーザープリンタ（モノクロ） |
| 解像度 | 600 dpi |
| 用紙 | A4 普通紙（白） |
| 出力サイズ | QR コード 1 辺 = 4 cm（v07 の場合 約 7 dpi/module） |
| 変換コマンド | `convert -density 300 -units PixelsPerInch input.png output_print.png` |

> 印刷時の出力サイズは `generate_opqr_batch.js` の cellSize=8px・margin=4cells 設定から計算される実ピクセル数（v07: 424px）に基づく。

### 5.3 スキャン条件

| 項目 | 仕様 |
|------|------|
| スキャナ | 平台スキャナ（例: Epson ES-400 II または相当品） |
| 解像度 | 300 dpi |
| カラーモード | グレースケール |
| ファイル形式 | PNG（非圧縮） |

### 5.4 評価手順

1. 全 QR コード画像（OPQR × noise × version × 10画像、比較手法 × method × version × 10画像）を印刷する。
2. 各シートを平台スキャナで 300 dpi グレースケールスキャン。
3. スキャン画像から QR コード領域を手動またはスクリプトでクロップ。
4. `evaluate_qr.py --opqr` 等のスクリプトをスキャン画像ディレクトリに適用（要: manifest 更新）。
5. 各手法・条件ごとの成功率を集計し `comparison_table.md` の TBD セルを更新。

### 5.5 追加検討条件

- インクジェットプリンタ（参考比較用）
- 600 dpi vs 300 dpi 出力の比較

## 6. Phase 3：カメラ評価（TBD）

### 6.1 目的

スマートフォンカメラによる現実的な読み取り性能を測定する。視点距離・傾き・照明条件を系統的に変化させる。

### 6.2 実験機材

| 機材 | 仕様 |
|------|------|
| 撮影端末 | iPhone 16 Pro（メインカメラ 48 MP, f/1.78） |
| 補助端末 | Android（Google Pixel 9、比較用） |
| 印刷物 | Phase 2 と同一の 600 dpi 印刷 |
| 照明 | 室内蛍光灯（500 lux 程度）/ 自然光 |
| 三脚 | 固定角度・距離の再現性確保用 |

### 6.3 撮影条件マトリクス

| 条件 ID | 距離 | 傾き | 照明 |
|---------|------|------|------|
| C1 | 15 cm | 0° | 室内蛍光灯 |
| C2 | 20 cm | 0° | 室内蛍光灯 |
| C3 | 30 cm | 0° | 室内蛍光灯 |
| C4 | 20 cm | 30° (水平回転) | 室内蛍光灯 |
| C5 | 20 cm | 45° (水平回転) | 室内蛍光灯 |
| C6 | 20 cm | 15° (垂直傾け) | 室内蛍光灯 |
| C7 | 20 cm | 0° | 自然光（屋外） |
| C8 | 20 cm | 0° | 低照度（100 lux） |

> まず C2（最良条件）で評価し、Phase 1 結果と傾向が一致するか確認する。  
> 一致が確認されてから C3〜C8 に展開する。

### 6.4 評価手順

1. 各 QR コード印刷物について、各撮影条件で 3 回撮影する（n=3/条件）。
2. iOS カメラアプリで読み取り成功・失敗を記録（Shortcuts アプリで自動化可能）。
3. 撮影した写真を `evaluate_qr.py` に入力してソフトウェアデコードも行う。
4. アプリデコードとソフトウェアデコードの結果を別カラムで比較表に記録する。

### 6.5 注記

- OPQR はアプリ（OPQRcoder）から直接生成した QR コードが前提のため、`generate_opqr_batch.js` で生成した画像との同一性を確認すること。
- カメラ評価は Phase 2（印刷条件）の後に実施する（印刷物を再利用）。

## 7. 評価指標

| 指標 | 定義 | 計算方法 |
|------|------|---------|
| **読み取り成功率** (%) | デコード成功数 / 試行数 × 100 | `evaluate_qr.py` が自動計算 |
| **エラー率** (%) | 100 − 読み取り成功率 | 読み取り成功率の補数 |
| **デコード内容一致率** | 成功したデコードのうち、正解テキストと完全一致した割合 | 成功 = 一致とみなすため通常は同値 |

> 「読み取り成功率 = 100% − エラー率」の関係にある。  
> OPQR の理論値はエラー率 **0%**（padding 領域のみ変更のため ECC 未消費）。

---

## 8. 統計処理

- 成功率は各手法・バージョン・ノイズ条件ごとに **10 画像の平均値** として報告する。
- Phase 2・3 で n が増えた場合は **95% Wilson スコア信頼区間** を付記する。
- Phase 1〜3 の間で成功率の変化量を「劣化率」として報告し、手法間で比較する。
